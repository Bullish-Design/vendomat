## Part 1 — `collection-add` and the install on `devman`

**The change.** In a new `nix-meta` lane, `collection-post-receive`, in its own workspace (`.worktrees/collection-post-receive`), `scripts/collection-add` now installs two hooks: the existing `pre-receive` and the new `post-receive`. A new mode, `collection-add --hooks <repo>`, rewrites the hooks of an existing repository. It refuses a directory with no export marker. The embedded `post-receive` text is byte-identical to `hooks/collection-post-receive` in this repository (checked with `diff`). I did not touch the main `nix-meta` checkout or the `v4-attic-ssd-storage` lane.

**Scratch test** (`VENDOMAT_COLLECTION` set to a temporary directory):

- `collection-add demo` created a repository with both hooks, mode 755, and the export marker.
- A tag push over `file://` printed `collection: working tree now shows v1.0.0`; the tree held the files.
- A branch push was refused by `pre-receive`.
- `collection-add --hooks demo` refreshed the hooks. `--hooks plain` on a directory with no marker exited 1. `collection-add demo` on an existing directory exited 1.

**Install on the live `devman`.** `collection-add --hooks devman` ran once.

- `pre-receive` was identical before and after (checked with `diff` against a saved copy). The live text equals the text in the script.
- `post-receive` is new, mode 755, and equals `hooks/collection-post-receive`.
- I ran the hook by hand in the live repository (`GIT_DIR=. ./hooks/post-receive`). It printed nothing and exited 0, because the tree was already at `v0.7.0`.
- `git for-each-ref` for `devman` and `git ls-remote git://server/devman` are identical to the state before. The tree is clean at `v0.7.0`. `pydantic` and `silverbullet` have no new hook.

**End-to-end on a copy.** A pushed tag would stay in the live collection for good, because the hook refuses to delete or move a tag. So I copied `devman` with its hooks (`cp -a`) to a scratch directory and pushed there:

- A new tag `v0.8.0` was accepted. The pusher saw `working tree now shows v0.8.0`. The tree held the new file and was clean.
- A branch push was refused (`pre-receive hook declined`).
- A forced push of a moved `v0.7.0` was refused.
- `git for-each-ref` in the live `devman` was unchanged afterward.

The push used `file://`, not SSH. Both run `receive-pack` with the same hooks.
