## Part 2 — the real run on `server`

**Inputs.** A fresh project at `~/.local/state/vendomat/v5/2026-10-08/fixtures/store-step-real` with this registry:

```toml
[forge]
url = "git://100.124.67.32"

[inputs]
devman = { ref = "refs/tags/v0.7.0" }
```

and `flake-outputs.nix` holding `inputs: { }`. The default source root `~/vendor` applied. Raw logs are in `~/.local/state/vendomat/v5/2026-10-08/logs/store-real/`.

**State before.** `/home/andrew/vendor/devman`: `HEAD` was `ref: refs/heads/master` (unborn), no checked-out files, tag `v0.7.0` (tag object `a66d84a`, commit `4c9927a`), hook and export marker present, no `origin`. `pydantic` and `silverbullet` had neither hook nor marker and a clean tree. `git ls-remote git://server/devman` listed the tag and its peeled commit.

**Commands and results.**

1. `sync --collection --dry-run --root <project>`: exit 0. It printed `would write flake.nix` and `collection:devman: planned: newest release would check out v0.7.0 (4c9927a)`. It wrote no `flake.nix` and left `HEAD` as it was. It printed nothing about `pydantic` or `silverbullet`.
2. `sync --collection --root <project>`: exit 0. It wrote `flake.nix` and printed `collection:devman: updated: newest release checked out v0.7.0 (4c9927a)`.
3. The same command again: `unchanged flake.nix` and `collection:devman: unchanged: newest release at v0.7.0 (4c9927a)`.
4. `path devman --root <project>`: printed `/nix/store/9z68gh75nwf9m7hghqb9vimzpmfzq28h-source`; `vendomat.toml` was not changed and no `flake.lock` appeared.

**State after.** `HEAD` of `devman` is the detached commit `4c9927a` (`git describe` gives `v0.7.0`). The working tree holds the release files (`AGENTS.md`, `devenv.nix`, and the rest) and `git status` is clean. `git for-each-ref` is identical to the state before. `pydantic` and `silverbullet` have the same `HEAD` and a clean tree as before.

**What `git://` serves.**

- The tags are identical: `git ls-remote` lists the same tag and peeled commit.
- **One line is new.** The daemon now also advertises `HEAD` as `4c9927a`. Before, `HEAD` was unborn and the daemon advertised no `HEAD`. A new `git clone git://server/devman` therefore succeeds, checks out `v0.7.0` in a detached state, and prints Git's detached-HEAD notice. Before this change a clone had no `HEAD` to check out. Nix selects by `ref=refs/tags/…`, so it does not use `HEAD`. This follows from the detached checkout that `STORE-013` and `STORE-022` require. Inference: a checkout that keeps `HEAD` on the unborn branch would show every file as staged and make the tree read dirty.
- I did not push a tag after the checkout. Inference: a tag push does not need a branch, and the hook looks only at the pushed ref.

## Not covered

- No `keep` or `mirror` entry ran on `server`. The unit and Nix tests cover them, using local repositories and a loopback daemon.
- A push-time hook that refreshes the tree after a tag push is not built (`STORE-013` allows "a hook or `sync`"). `sync --collection` is the only refresh.
- `STORE-010` (rebuild the collection from authoring repositories) is not built.
- The explicit use of `backup` is not built.
- The `framework` checks in PV-19 stay owner-reported.
- `vendomat path` reads the lock through Nix with `--no-write-lock-file`. If `vendomat.toml` changed and `flake.nix` was regenerated after the last `nix flake lock`, Nix resolves the new input in memory and `path` prints that path, not a locked one. Run `nix flake lock` first when you need the locked path.
