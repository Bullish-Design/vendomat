## Inference

The documented recursive-update merge does not satisfy the package-list preservation claim. A module containing `lib.mkMerge` contributions does preserve both package lists on this pinned NixOS module system. The fixture supports using the native module merge for `extra` and install paths.

The candidate scan supports optional face exports: most observed module providers expose only one face, and only one of 18 exposes all three. The helper can still offer all three generated modules; each flake should export only the faces it supports. The scan does not prove every candidate input in the wider registry.

The fixture does not prove that every real candidate input works with the helper, nor does it prove consumer activation in a complete generated NixOS/Home Manager system.

## Decision

Revise `MOD-007` to specify native module merging instead of recursive attribute update, and add a successor requirement for list preservation. Preserve `INP-002` as historical; add a new requirement that inputs may export only the module faces they implement. Keep `MOD-001` as the helper's three-face convenience interface, but allow an authored flake to publish a subset of those faces. PV-12 must assign unused IDs and update the concept, specification, guide, and decisions table together.
