## Inference

The bridge is a valid flake `outputs` function on Nix 2.34.7. Nix hands it every declared input and `self`, and the project file can use all of them. A generated flake needs no shell, no `devenv` input, and no module scan. Selecting a module is a project action, and the module stays inactive until its own `enable` option is true.

The proposed `[follows]` table can drive the generator, with three consequences. The generator cannot know whether a child declares `nixpkgs` without fetching it, so the Nix warning is the only check for that case. Nix is silent about a non-flake child, so the registry check must reject that case itself. A dangling target is already a Nix error, but the registry check can name the entry earlier.

The draft claim that `ref` and `rev` "pass through verbatim" as separate flake input attributes is false for string-URL inputs. The generator must append them to the URL as query parameters.

The one-node result still needs every authored flake in the chain to follow its parent. This fixture used controlled flakes and does not apply to arbitrary inputs.

## Decision

Adopt the bridge, the `[follows]` table, and query-form `ref`/`rev` as the proposed contract. Record the successor requirements in `SPEC-V5.md`. Keep every claim here limited to this fixture. The generator (`GEN-*`), a private source host, a cache, a cold store, and the host CLI check (F8) remain unproved.
