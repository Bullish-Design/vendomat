# PV-15 — private source host and cache-served sources

**Date and time:** 2026-10-08 15:50 to 16:05 EDT
**Host or virtual machine:** server, x86_64-linux; a disposable Attic 0.1.0 on a loopback port
**State:** blocked — no private Git host exists. Attic can serve a flake source only as a hash-locked store path, not as a Git remote.
**Related requirements:** REG-010, STORE-001, STORE-006, STORE-007, CACHE-001, CACHE-002.
**Tools:** Nix 2.34.7; Attic 0.1.0; Tailscale 1.98.8. A subagent ran the probes; the lead spot-checked its logs.
**Expected:** a portable URL for a private personal repository works from the intended host.

## Observations

- Every remote URL in `~/Documents/Projects/*/.git/config` is GitHub. GitHub is the owner's secondary copy of local repositories and not part of the Vendomat pipeline.
- The only matching services are `sshd` (port 22), `atticd`, and the Tailscale Serve units. No Forgejo, Gitea, Gitolite, cgit, or `git-daemon`; no `git` user; nothing on port 9418.
- Tailnet peers listed: `server`, `framework` (active), `samsung-book` (active), `tower` (idle), and two offline. Reachability of `framework` was not tested.
- In a throwaway Attic (temporary key, token, and data, since deleted), a cold store with the cache credential evaluated a `tarball` lock and a `git` lock whose origin (`git.invalid`) was unreachable. Both used the locked hash. Without the credential the evaluation fell back to the origin and failed.
- A bare store-path flake reference does not substitute by itself. `nix build /nix/store/…-source` does. A copy of the root alone does not carry its inputs; `nix flake archive` does.
- The probe added two small source paths to the host store. Garbage collection removes them.

Raw evidence: `/home/andrew/.local/state/vendomat/v5/2026-10-08/blockers/` (`C1.log` to `C9.log`, `REPORT.md`).

## Inference

No portable `git+https` or `git+ssh` URL works for private repositories today. Attic can serve a source as a path with a locked hash if each deploy first runs `nix flake archive --to <cache>` and the consumer holds the cache key and credential. That is not a Git remote: PV-03 and `STORE-001` stay open, and updates still need an origin. `git+ssh` through `server`'s `sshd` is a candidate that nobody tested; it needs SSH key trust from the other machine.

## Decision

Keep private source acceptance blocked. Do not change production Attic state or push sources to it. This is an owner decision: recommend a real Git remote on a host both machines reach. Forgejo on the tailnet, or `git+ssh` through `server`, keeps `STORE-001` and `STORE-006` honest. Cache-served sources add a publish step before each deploy and tie source access to the cache credential.

## Follow-up

After the owner chooses, test a clone from `framework` before any lock change. If the owner chooses cache-served sources, test against a test cache on the real Attic with an owner-supplied token.
