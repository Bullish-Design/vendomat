## Inference

Attic can serve this closure to a cold Nix store when the caller already has the pull credential and uses the host-local route. This does not prove installer access, first-boot access, or a cold laptop download. The current Serve URL and `attic use` output do not agree on the route prefix. The host lacks the private cache trust key and credential in its Nix configuration.

## Decision

Block CACHE-007 and BOOT-019 until an installer route, trust key, pull credential, source flake, and cold VM or image fixture are specified and tested. Keep the partial host-local cold-store result. Do not claim a laptop install downloads from Attic. Keep production cache settings unchanged.

## Follow-up

Rework the bootstrap design to make the installer able to reach the cache or receive a verified closure before first boot. Then repeat the transfer in a disposable VM with a cold store. Keep the actual private credential out of tracked files and logs.

## Addendum 2026-10-08 (second session): cold installer VM without a credential

**State:** partial. The route is reachable from a cold VM and refuses an anonymous request. No closure was fetched.
**Tools:** Nix 2.34.7; Tailscale 1.98.8; nixpkgs `7c8764b7` (the PV-11 pin). A subagent built and ran the VM; the lead checked `B3-vm-run-masked2.log`.

Design of the full test. The installer needs four things before first boot. They are the route with its `/attic` prefix (`https://<tailnet-host>/attic/vendomat`), the public key `vendomat:SRJCMEnuScYDRmGId+o9nkXn+MaLpQvDTHs5AfnRQgA=`, a pull credential, and the source of the system flake or a prebuilt closure. Run `nix build --max-jobs 0 --store local?root=<empty>` against the 121-path closure with `--option substituters`, `--option trusted-public-keys`, and `--option netrc-file <runtime file>`. The credential file must live outside the Nix store and every tracked file (`CACHE-002`).

Observed in a disposable NixOS test VM on `/dev/kvm`, with no credential: the loopback route (`http://10.0.2.2:8089/vendomat`, the guest's view of host loopback) returned 401 for `nix-cache-info` and the narinfo. The tailnet route with the `/attic` prefix returned 401. The tailnet route without the prefix returned 404. In the guest, `nix build` of `/nix/store/l6imh86vz9ic4cmyikisxszrrfvs7ab8-nvim-review-editor` through each route exited 1 with `HTTP error 401` and `no substituter that can build it`. The path stayed absent. Production services were active before and after. No credential was read.

Inference: a cold guest reaches the real route and meets a clean authorization failure, so the credential is the only missing piece on this path. The guest reached the tailnet name through the host's identity; a laptop has none until it joins the tailnet, so this does not prove laptop access. The earlier host alternate-store fetch remains evidence for that path only. `CACHE-007` and `BOOT-019` stay blocked.

Owner decision (recommendation first): deliver a root-only (mode 0600), pull-only, short-lived credential file from the installer medium to `/run` at runtime, and pass it with `--option netrc-file`. Consequence: the medium holds a secret, and a laptop still needs a route to the tailnet. Alternatives: a prompt (can leak into shell history), a fetch from `server` over SSH (moves the problem to key delivery), a short-lived tailnet auth key (adds a second secret), or a verified prebuilt closure on the medium (no network credential, but it does not prove the cache route). Reject a credential baked into the image or the Nix store.

Next safe action after the owner chooses: extend the VM test to attach a test credential file at runtime and fetch the full 121-path closure with a new pull-only token.
