## Part 1 — the hook, fixture results

The tests make a non-bare repository the way `collection-add` does (`git init`, the `pre-receive` rule, the export marker) and add the hook as `post-receive`. They push tags into it over `file://`, so Git runs the real `receive-pack` path with both hooks. No Nix and no network.

`devenv shell -- testee verify --tool pytest --target tests/test_collection_hook.py --mode detailed`: 8 passed.

- A first tag push fills an unborn, empty repository. The tree shows the tag, the checkout is detached, `git status` is clean, and the pusher sees `collection: working tree now shows v0.7.0`.
- A newer tag moves the tree. An older tag pushed later (`v0.8.0` after `v0.10.0`) leaves the tree at `v0.10.0`: the order is version order, not push order.
- A dirty tree stays as it is, the push succeeds, and the pusher sees `uncommitted changes`.
- A held `.git/index.lock` makes the checkout fail. The push still succeeds, and the pusher sees `could not check out`.
- A branch push is still refused by `pre-receive`. Refs and tree stay as they were.
- After the hook runs, `sync --collection` reports `unchanged` for the repository, and the tags are as they were. The hook and `refresh_collection` agree.
- A bare repository is ignored.

## Part 2 — the keep run on `server`

**Inputs.** A fresh project at `~/.local/state/vendomat/v5/2026-10-08/fixtures/store-step-keep`:

```toml
[forge]
url = "git://100.124.67.32"

[inputs]
devman = { ref = "refs/tags/v0.7.0", keep = true }
```

The source root was a new directory, `…/fixtures/keep-root-1`, set with `VENDOMAT_SOURCE_ROOT`. `~/vendor` was not the target of any write. Raw output is in `~/.local/state/vendomat/v5/2026-10-08/logs/store-keep/`.

1. `sync --dry-run`: `would clone git://100.124.67.32/devman to …/keep-root-1/devman, then check out v0.7.0`. The root directory did not exist afterward.
2. `sync`: exit 0. `devman: cloned … at v0.7.0 (4c9927a)`. The clone has `origin` set to `git://100.124.67.32/devman`, a clean tree, and the release files.
3. `sync` again: `devman: unchanged … no new tags; at v0.7.0 (4c9927a)`.
4. `sync` with `VENDOMAT_SOURCE_ROOT=/home/andrew/vendor` (the real collection, where `devman` has no `origin`): `devman: skipped: … has no origin: it is the collection's own repository; left alone`. `git for-each-ref` and `git status` for `devman` are as before. `pydantic` and `silverbullet` have the same `HEAD` and a clean tree as before.

This is a real `keep` over `git://` from the live daemon. It reads from the collection and writes nowhere in it.
