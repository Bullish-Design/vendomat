## Inference

The specified sequence is internally inconsistent: `set` creates an uncommitted host file, while `apply` must refuse that state. A workable sequence is `set → diff → commit through Gitman → apply`. Define `diff`'s before-state as the last committed host configuration and its after-state as the current host file. This lets `diff` run before the commit and gives `apply` a clean input.

The fixture shows that evaluating a useful delta is feasible for selected option values. It does not establish a universal JSON representation for Nix values, implement dirty-file checks, or prove activation and rollback. A future implementation must either report unsupported values explicitly or restrict its serialized delta to values with a stable JSON representation.

## Decision

Keep CLI-009 to CLI-013. Add `CLI-015` for the exact diff baseline: the last committed host configuration is the before-state; the current host file is the after-state. Update the guide so it commits the host edit through Gitman between `diff` and `apply`. Preserve `CLI-012`'s refusal on dirty files. The force syntax and exact bypass scope remain proposed; if retained, force should bypass only the dirty-file guard. Keep `CLI-013` proposed until a disposable VM proves generation rollback.
