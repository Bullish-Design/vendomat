## Commands

1. Build the repository with `gitman init`, `seed`, `repair`, and `release --version 1.0.0`.
2. `git daemon --reuseaddr --base-path=<dir> --export-all --listen=127.0.0.1 --port=<p> --detach`.
3. In a consumer flake with `inputs.lib.url = "git://127.0.0.1:<p>/lib-a?ref=refs/tags/v1.0.0"`: `nix flake lock`, then `nix eval --raw .#marker`.
4. Stop the daemon. Evaluate again in the same store. Then evaluate in a cold store with an empty fetcher cache.
5. Read `/proc/<pid>/stat` ticks over 20 idle seconds, plus resident memory, threads, and child processes.
6. Repeat step 3 with `?ref=…&rev=…`, `?rev=…` alone, and no query.
7. `ssh -o BatchMode=yes localhost true` with a temporary known-hosts file.

## Observations

- The lock recorded `type git`, `url git://127.0.0.1:<p>/lib-a`, `ref refs/tags/v1.0.0`, the revision, and the NAR hash. Evaluation returned `lib-a-v1`.
- With the daemon stopped, the same store evaluated again with exit 0. A cold store with an empty cache failed: `Failed to fetch git repository 'git://127.0.0.1:<p>/lib-a'`.
- Idle daemon: 0 CPU ticks in 20 seconds (100 ticks = 1 second of one core), resident memory 1,832 kB, 1 thread, state `S`, no child process.
- Tag only, tag with rev, and rev alone all locked and evaluated. The URL with no query failed on this repository: `Failed to fetch git repository`. The repository is a Gitman colocated clone, whose Git HEAD is not a branch; the cause was not isolated.
- `ssh -o BatchMode=yes localhost true` returned `Permission denied (publickey)`. SSH key login from `server` to itself is not set up, so `git+ssh` was not tested. `framework` to `server` was not tested.
- No daemon process or listener remained after the runs.

## Inference

A read-only `git://` daemon is enough for Nix to fetch a tagged release with no credential. It sleeps when idle, so it costs no CPU core. Nix keeps a fetched revision, so a machine off the tailnet still evaluates what it already fetched and fails only for a revision it never had. The tag rule in `REG-017` is Vendomat policy, because Nix also accepts a rev alone.

The daemon serves every repository under its base path to every device that can reach the port. The tailnet is the access boundary.

## Decision

Use `git://` for reads. Keep SSH for release pushes and set up its keys before Step 6.3. Record `NAT-014` to `NAT-016`. This is a loopback result. A fetch from `framework` over the tailnet is the open proof for `STORE-008`.
