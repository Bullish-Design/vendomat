### Departures that matter

1. RT7 and RT8 need a probe. `definitionsWithLocations` never merges a value, so Nix rejects nothing
   in a plain `truth` request. The runner adds an own option `dpyRtProbe` to each generated module.
   The probe forces the defined values and `config.assertions` under `tryEval`, and answers a
   string. It does not touch `nix/`. Limit: the class `type-error` means "forcing the values threw".
   It also covers a throwing `apply`.
2. Errors that `tryEval` cannot catch abort the batch. The runner classifies those from stderr (ANSI
   stripped). `NO_COLOR` does not remove color from Nix errors.
3. RT4 skips fixtures with `imports` (reason `has-imports`) and fixtures with `no-literal-fields`.
   The syntax reader sees only `devenv.nix`; truth merges all files.
4. RT1 and RT4 skip for the subtree `*` (`no-subtree`). RT2, RT3, RT5, and RT6 run once per fixture
   and repeat per subtree.
5. An `alone` fixture skips the evaluating checks (`alone-needs-project`) unless `alone_project` is
   passed to `run`. The `alone_project` of Step 7 is not wired in.
6. Generated case labels are `generated/<subtree>/<id>`. Case ids repeat across subtrees, and a first
   run overwrote results; the label fix removed this.
7. `dpy rt --smoke` and `--seed` are additions to the guide.
8. The check name is `pytest`, not `unit`.
9. The report cannot measure: truth stability (Step 7 records it), RT8 per-field enumeration beyond
   the generator report, and the warm-cache state of the run time.
10. Development iteration used `python -m pytest <file>` and `dpy` in `devenv shell`. The gate runs
    used Testee only.

### RT5 strict (report `~/.local/state/devenv-py/canon/REPORT.md`)

Workspace `gitman-workspaces/dpy-canon`, base `70d7419f`. Testee run
`20261011T131425Z-638700540816` PASS.

- `writer_nix.canonical_definitions` merges all definitions into one tree (reader insert rules,
  first-seen order). `render` writes one dotted binding per leaf. A set inside a list or a tagged
  value stays as a set. `{}` is a leaf.
- `read_syntax.py` reads a plain `./x` or `../x` path literal (no `${`) as a typed `{"$path": ...}`.
  `<x>`, `/abs`, `~/x`, and interpolated paths stay `$nix`. `_is_tree` treats only `$nix`, `$pkg`,
  `$path`, and `$priority` as tag keys, so an attribute named `"${x}"` is an ordinary key. New
  helpers: `insert_path`, `is_tree`.
- `roundtrip.py`: RT5 is strict. The first render equals the render of the read of the first render.
  The earlier comparison of the second and third render, and the `strict` info flag, are gone.
- Result (`dpy rt --smoke`, run `canon-smoke`, 9 fixture-subtree cases): RT2 9 of 9, RT3 9 of 9,
  RT4 2 pass and 7 skip, RT5 9 of 9 strict, RT6 9 of 9.
- Departures: canonicalization lives in `render`, not in the builders, so `contribution_from_*`
  return raw definitions and every writer caller (generated cases too) gets the layout. The agent ran
  `ruff format` once directly, against the "no direct ruff" rule. Path literals now count as typed in
  `tally` and `classify`, so the fleet typed ratios rise slightly.
