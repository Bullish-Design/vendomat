observation. Every fact cites a record. Every decision is a recommendation that the owner may revise.

**What this session did not do.**

**F6 FAIL and its fix.** Project 19 section 5 and the first concept say a missing cache never
blocks a build. S6 step 5b disproves this. With Nix 2.34.8 defaults (`fallback = false`,
`connect-timeout = 15`, `download-attempts = 5`), a refused cache makes `nix-store -r`, `nix-build`,
and `nix build` exit 1 after 5 s. A frozen cache fails after 20 to 44 s. A 404 for an absent path
already falls back. `--option fallback true` restores the local build in every case (5b, 5c).

[DOOR-046](../REQUIREMENTS.md) fixes this. A host derives the substituter URL and public key from the
inventory mark. It sets `fallback = true` and a short `connect-timeout`. A core with no mark sets
none. The fixture proves `fallback = true`. It does not prove the short timeout with fallback.
No module implements either setting yet.

## 10. Incidents

### 10.1 `devenv gc` runs (S5 incident 1)

The S5 agent ran `devenv gc` twice on the fork before it read the code. Both runs hung with no
output. The agent killed them after 185 s and 20 s. The nix-daemon journal shows
`unexpected Nix daemon error: error: interrupted by the user` at 22:18:11 and 22:22:14. `strace`
showed only `git` as a child process.

Code reading by the orchestrator: `devenv gc` deletes dangling links in `~/.local/share/devenv/gc`.
It then asks the daemon to delete the specific old devenv environment paths those links name
(`collect_garbage` with explicit paths). Nix refuses to delete a live path.

- **Effect:** at most some unrooted old devenv shell closures were deleted. They rebuild on demand.
- **Not a store-wide collection.** No `nix-collect-garbage` ran.
- **Free space:** it rose 0.8 GiB between two readings. No evidence ties that to these runs.
- **Open:** the `gc` row of the S5 guard matrix is not tested. Do not run `devenv gc` without reading
  its code first.
